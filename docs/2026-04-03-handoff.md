# 2026-04-03 Handoff

## Context

This repository is being repositioned from a generic coffee recommendation demo into a GeoAI proof of concept for GIS reviewers.

The intended PoC is:

- Limited to Jiyugaoka, Tokyo
- Limited to coffee shops and coffee bean stores
- Driven by ArcGIS-centered logic rather than a generic LLM
- Able to accept varied Japanese natural language input
- Allowed to return a top 3 set instead of a single best answer
- Optionally able to narrow needs through follow-up questions

## ArcGIS Account Findings

### Important constraint

ArcGIS for Personal Use appears unsuitable for API key authentication.

Based on Esri official documentation reviewed during this session:

- API key authentication is not the safe assumption for ArcGIS for Personal Use
- OAuth-based app registration looks more promising than API key usage

This matters because the current app code uses `VITE_ARCGIS_API_KEY`, which is likely the wrong direction for the target account type.

### What the UI investigation suggested

Observed in ArcGIS Online UI:

- `Developer credentials` is visible in the left navigation
- `OAuth 2.0 credentials` is visible
- `API key credentials` is visible, but there is no evidence yet that this path is viable for Personal Use
- App creation is available

Observed during app creation:

- `Web マッピング` requires HTTPS
- `http://localhost:5173` is rejected
- Therefore, browser-based OAuth app registration may require:
  - `https://localhost:...`, or
  - some HTTPS dev tunnel / hosted callback URL, or
  - a different application type

### Current interpretation

Most likely:

- API key route: weak / likely not appropriate
- OAuth route: plausible
- ArcGIS usage is not blocked entirely, but the auth approach must change

## Architectural Question Still Open

The biggest unresolved question is:

What ArcGIS capability should be the real engine of recommendation?

This was not resolved yet.

Possible directions:

1. ArcGIS-only approach
- Use ArcGIS-authenticated services only
- Preferable for credibility with GIS reviewers
- Risk: Personal Use service availability may be narrower than hoped

2. Google Places + ArcGIS approach
- Use Google Places as the venue source
- Use ArcGIS for spatial scope, mapping, ranking explanation, and GIS framing
- More realistic if ArcGIS venue discovery is limited
- Risk: reviewers may feel ArcGIS is only decorative unless the spatial reasoning is clearly central
